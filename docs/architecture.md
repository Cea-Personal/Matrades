# Matrades Architecture

Matrades is a modular monolith with FastAPI, Celery, a dedicated agent worker, Next.js, PostgreSQL/TimescaleDB/pgvector, and Redis. PostgreSQL is authoritative for workflows, approvals, versions, reservations, jobs, audit, and the transactional outbox. Redis is only cache, lock, rate-limit, and delivery acceleration. SSE projects outbox events and never becomes a system of record.

Deterministic services own account truth, financial math, effective-policy selection, risk decisions, strategy compilation, lifecycle transitions, reconciliation, and performance. Agent roles interpret bounded evidence. The seventeen protected logical agents use `CODEX_APP_SERVER` by default. Their project-scoped Codex-native role definitions live in `.codex/agents/`; the agent worker starts an orchestrator thread and delegates specialist work with Codex's native `spawnAgent` flow. Every role is read-only and bounded by the supplied evidence contract. A versioned agent/profile assignment may select `LITELLM_GATEWAY`; fallbacks must remain within that runtime and exhaustion fails safely. System and user prompts independently resolve agent override → orchestrator → platform. Tool permissions are separately versioned and forbid broker writes, hard-policy or guardrail mutation, raw credentials, and strategy activation.

Unconfigured agents receive role-specific model and reasoning defaults from `.codex/agents/*.toml`, read through `modules/agents/model_assignments.py`. The API and worker resolve these defaults and owner-scoped saved overrides through `modules/agents/configuration.py`. Files are read afresh rather than held in a startup snapshot; an explicitly assigned `ModelProfile` overrides the native default. Requested models and verified runtime model evidence are recorded separately: a configured or requested model alone is not proof of the model used.

The MT5 bridge exposes authenticated account, position, order/history, market data, heartbeat, and capability records. Read-only adapters and bounded broker command adapters have separate interfaces. Autonomous broker writes require deterministic Trade Plan, risk, policy, account-permission, kill-switch, freshness, idempotency, and reconciliation checks. AI output and strategy-proposal acceptance cannot authorize an order. Legacy HIL routes remain compatibility boundaries, not routine trade-approval gates.

When `MATRADES_MT5_RUNTIME_CONTROL_URL` is configured, authenticated session issuance calls the protected cloud MT5 runtime controller before persisting a session. The controller initializes Wine, launches MT5 if necessary, and waits for its process to be alive. A controller failure returns `503` before a session record is persisted. Local host startup remains available when no remote URL is configured; Docker deployments must run the controller where the Wine/MT5 installation exists.

External adapters implement timeouts, freshness, provenance, rate limits, health, and closed circuit breakers. Knowledge retrieval is owner scoped and context-only; current account, market, policy, risk, strategy identity, and performance facts always route to structured stores.

Knowledge search and assistant retrieval optionally use Cohere as a second-stage reranker. Store an encrypted `COHERE` credential and connection under Connections, then select it under Knowledge → Cohere knowledge reranking. `PUT /knowledge/reranking-configuration` verifies the selected model with synthetic text before activation; `DELETE` disables reranking without deleting the connection or re-embedding documents. Configuration is owner-scoped and remains off until explicitly enabled.

Market and strategy research use the same audited hybrid retrieval service as Knowledge search. Market reviewers share one bounded pack per lane and research cycle (up to five excerpts); strategy research receives up to twelve excerpts selected across the authorized index, with at most three candidate segments per source unless a transcript is explicitly pinned. This avoids selecting transcripts solely by recency and prevents a long transcript from crowding out other research. Embeddings are compared only within matching model/dimension spaces; embedding outages fall back visibly to lexical matching, and Cohere outages retain the existing hybrid fallback. Missing optional knowledge does not block otherwise valid market research. A pinned transcript remains mandatory for explicitly source-pinned extraction.

Agent access is **backend retrieval**, not a callable `knowledge.search` tool. The backend passes `knowledge_context`, citation/reference IDs and `knowledge_retrieval` audit/status metadata to the model. Domain tool permission/audit lists are empty because neither runtime registers callable market/knowledge tools. Retrieved text is untrusted context, never instructions, live news/prices, market authority, risk policy, approval or a reinforcement-learning reward. No model-weight training is performed by this pipeline.

SerpApi discovery currently uses Google `site:youtube.com` search. It excludes videos discovered or indexed previously by the same owner across queries, and persists a normalized-query cursor. Each invocation inspects at most three pages of twenty requested search results; it resumes on the same page when results remain, otherwise advances using the returned pagination offset. Provider pagination URLs are never fetched directly. The active connection row serializes concurrent discovery transactions in PostgreSQL. Exhausted results can yield fewer than the requested number, including zero; the UI reports that honestly and never offers empty transcript ingestion. Search history retains actions for fetching saved `SEARCHED` runs and explicitly retrying `PARTIAL`/`FAILED` transcripts without rediscovery or re-ingesting successful videos. Search history/cursors do not expire automatically, so repeatedly searching the same query does not reset exclusion history.

Scheduled YouTube discovery supports `query_mode=AUTO_MARKET` (the default for new schedules) and `FIXED`. Legacy saved schedules without this field retain their fixed query until edited. The automatic planner uses the latest finished market cycle per active owner account, including usable selections from degraded cycles, never old selections made recent by updates. It rejects future/naive timestamps and evidence older than 72 hours; this freshness window is for educational query planning only and does not relax trading freshness gates. Across the four highest-scored current selections, it chooses the least-searched pair, then the least-searched regime-compatible topic: trend/pullback/momentum/breakout for trending markets, mean-reversion/range/liquidity/breakout for ranging markets, with walk-forward/cost/robustness research in both rotations. Missing fresh selections yield rotating general educational topics with no invented current pair or regime. Planning is deterministic and makes no model or provider calls. Each run keeps the exact generated query, topic, pair, regime, account, research-run/selection IDs and reason in `query_plan`; the UI displays a preview (recomputed at scheduling time) and the recorded rationale. This remains one query per scheduled run with the existing video/page budget, not four paid searches.

YouTube knowledge ingestion is deliberately two-stage. `POST /knowledge/youtube/search` uses the owner’s SerpApi connection to discover and persist only bounded YouTube metadata; `POST /knowledge/youtube/runs/{run_id}/transcripts` then fetches captions only for that persisted result set, stores the transcript as a normal embedded `knowledge_source`, and records per-video success, duplicate, or unavailable status. Scheduled jobs execute the same stages and preserve `SEARCHED`, `TRANSCRIPTS_RUNNING`, `PARTIAL`, and `SUCCEEDED` state. These transcript sources carry `youtube`, `transcript`, and `trading` tags, so they participate in Knowledge Assistant retrieval and strategy research as context-only evidence. An extraction request can explicitly pin a transcript through `knowledge_source_id`; otherwise strategy research retrieves relevant sources across the index. Retrieved evidence is cited and converted by the strategy agent into a typed hypothesis and deterministic rules; the validated sequence is transcript → hypothesis → rules → preliminary/formal backtest → validation → paper evidence → risk-validated Trade Plan. Transcript text never directly becomes an order or reinforcement-learning reward; even strategies passing the recorded gates remain subject to current account and execution checks.

The retrieval order is owner/lifecycle/metadata filtering → lexical/vector hybrid scoring → a bounded pool of 20–100 candidates (50 by default) → [Cohere v2 Rerank](https://docs.cohere.com/reference/rerank) → the requested citation limit. The query and authorized candidate text are sent to Cohere; API keys are resolved only server-side, and testing/reranking incurs provider usage. Supported models are `rerank-v4.0-pro` (default), `rerank-v4.0-fast`, and `rerank-v3.5`. Provider indexes must be unique and in range, and scores must be finite; provider text never replaces stored evidence. Retrieval audits record reranking state, model, configuration version, and final citation IDs, never keys or query text. A timeout, bad response, or unavailable connection retains hybrid order with `DEGRADED` metadata and a visible assistant/search warning. No configured reranker preserves the existing hybrid behavior.

Completed market cycles automatically queue one strategy research job per READY lane's selected pair. Each job pins its account, selection, provider, listing and specification. Stable job IDs and a periodic dispatcher recover missed delivery; a missing history provider blocks only that pair. Broker-native MT5 research uses the pinned account's candle timeframe and exact broker symbol.

Strategy research supplies discovery candles to the native Strategy Researcher and withholds later candles for deterministic comparison of three hypotheses. New hypotheses include direction, next-bar entry, a volatility-based stop distance and increasing reward/risk targets. Screening simulates the same protection rules (including partial targets, gap stops and conservative stop-first ordering), ranks by passed gates then mean risk-adjusted return, and emits NO_TRADE if no hypothesis has positive net results after costs. This is preliminary evidence, not formal promotion.

The selected strategy produces an indicative entry, stop, profit targets, risk budget, invalidation conditions and timestamped expiry, visible on both Research and Strategies. Levels use the latest closed candle and are recalculated at the next-bar fill; unmet entry conditions yield WAIT, and expired candles yield STALE. After formal validation, paper outcomes are recorded through the paper-trading gate; only passing paper evidence moves the strategy to `APPROVED`. `POST /strategies/{id}/trade-plans` then revalidates the current signal against account, instrument, policy, and risk authority to create a READY or BLOCKED Trade Plan. Plan creation does not authorize execution or reserve capital; execution remains a separate revalidation boundary.
